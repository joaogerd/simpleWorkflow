1. Estrutura de um arquivo

format_version: 1

workflow:
  name: exemplo

context:
  python: python

tasks:
  - name: prepare
    argv: ["{python}", "-c", "print('prepare')"]
Palavra-chaveO que significa
format_versionVersão do formato YAML. Atualmente deve ser 1.
workflow.nameNome humano e persistente deste workflow.
contextValores reutilizáveis que podem aparecer como {placeholder}.
tasksLista das tarefas normais do workflow.

2. name e argv

Cada tarefa precisa de um nome único e de uma lista argv.

- name: convert
  argv:
    - python
    - convert.py
    - --input
    - data/raw.csv
    - --output
    - data/clean.csv

Cada item de argv é um argumento exato. Não é uma linha de shell. Isso evita ambiguidades com aspas, pipes e redirecionamento.

run: "python convert.py ..." não é suportado. Se precisar de shell, chame explicitamente um script versionado em argv.

3. Dependências com depends_on

tasks:
  - name: prepare
    argv: [python, prepare.py]

  - name: process
    depends_on: [prepare]
    argv: [python, process.py]

  - name: report
    depends_on: [process]
    argv: [python, report.py]

O simpleWorkflow executa a cadeia na ordem válida. Uma dependência falha bloqueia o downstream em vez de executá-lo silenciosamente.

4. Reutilizando valores com context

context:
  python: /usr/bin/python3
  case_dir: work/case01

tasks:
  - name: prepare
    argv: ["{python}", prepare.py, "{case_dir}"]

Placeholders podem ser usados em argv, cwd, env, PBS, inputs e outputs. Placeholder desconhecido causa erro antes da execução.

5. Diretório e ambiente: cwd e env

- name: model
  cwd: work
  env:
    OMP_NUM_THREADS: "4"
    CASE_NAME: "{case_name}"
  argv: [python, ../scripts/model.py]

cwd relativo é interpretado a partir do diretório do YAML. env adiciona variáveis específicas daquela tarefa; nomes e valores devem ser strings válidas.

6. Contratos de entrada e saída

- name: process
  argv: [python, process.py]
  inputs:
    required:
      - data/input.nc
    optional:
      - data/obs/*.nc4
  outputs:
    required:
      - data/output.nc

inputs.required precisa existir antes da execução. inputs.optional pode usar glob e pode não encontrar nada. outputs.required precisa existir depois que o processo terminar com sucesso.

Falhas nesses contratos produzem invalid-input ou invalid-output, que aparecem claramente na TUI.

7. Validando melhor uma saída

outputs:
  required:
    - data/output.nc
  checks:
    - path: data/output.nc
      kind: file
      nonempty: true
      min_size: 1024

Os checks genéricos verificam tipo, conteúdo vazio e tamanho mínimo. Validação científica específica deve permanecer em um programa ou tarefa versionada, não embutida no orquestrador.

8. Reuso, fingerprint e --force

Por padrão, entradas declaradas usam fingerprint metadata (caminho, tamanho e modificação). Para dados críticos menores:

input_fingerprint: sha256

Uma tarefa bem-sucedida pode ser reutilizada quando assinatura e contratos continuam válidos. Para executar novamente deliberadamente:

swf run workflow.yaml --force

9. Exemplo completo

format_version: 1

workflow:
  name: processamento_exemplo

context:
  python: python
  work: work

tasks:
  - name: prepare
    argv:
      - "{python}"
      - -c
      - "from pathlib import Path; Path('{work}').mkdir(exist_ok=True); Path('{work}/input.txt').write_text('dados')"
    outputs:
      required: ["{work}/input.txt"]

  - name: process
    depends_on: [prepare]
    argv:
      - "{python}"
      - -c
      - "from pathlib import Path; p=Path('{work}/input.txt'); Path('{work}/output.txt').write_text(p.read_text().upper())"
    inputs:
      required: ["{work}/input.txt"]
    outputs:
      required: ["{work}/output.txt"]
      checks:
        - path: "{work}/output.txt"
          kind: file
          nonempty: true

  - name: report
    depends_on: [process]
    argv: ["{python}", "-c", "print(open('{work}/output.txt').read())"]
swf validate workflow.yaml
swf plan workflow.yaml
swf run workflow.yaml --ui tui
