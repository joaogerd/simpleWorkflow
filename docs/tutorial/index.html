O que é o simpleWorkflow?

É um executor de workflows definidos em YAML. Você descreve tarefas, dependências, entradas e saídas; o simpleWorkflow decide a ordem correta, executa cada tarefa e registra o que aconteceu.

Ideia principal: você não precisa manter um servidor ou serviço de workflow. O estado fica junto do próprio caso, em .simpleworkflow/.

Workflow

O conjunto completo de tarefas que você quer executar.

Task

Uma unidade de trabalho: um programa e seus argumentos.

Attempt

Uma tentativa concreta de executar uma tarefa, com logs próprios.

1. Instalação

No estado atual do projeto, a instalação documentada parte do repositório GitHub. Não assuma que o pacote já está publicado em um índice Python.

python3 -m venv ~/.venvs/simpleworkflow
source ~/.venvs/simpleworkflow/bin/activate
git clone https://github.com/joaogerd/simpleWorkflow.git
cd simpleWorkflow
python -m pip install ".[tui]"
swf --help

Se algum desses passos for novidade para você, use o guia de instalação detalhado, que explica ambiente virtual, atualização e instalação para desenvolvimento.

2. Seu primeiro workflow

1

Crie uma pasta

mkdir meu-workflow
cd meu-workflow
2

Crie workflow.yaml

format_version: 1

workflow:
  name: meu_primeiro_workflow

tasks:
  - name: hello
    argv:
      - python
      - -c
      - "print('Olá do simpleWorkflow')"
Por que argv? Cada item é um argumento real do processo. O simpleWorkflow não interpreta uma string de shell escondida, o que deixa a execução mais previsível.

O que significam essas palavras?

PalavraNeste primeiro exemplo
format_versionDiz qual versão do formato YAML estamos usando.
workflowAbre a seção que descreve o workflow.
nameDá um nome ao workflow ou à tarefa.
tasksLista as tarefas que serão executadas.
argvDefine o programa e cada argumento que será passado a ele.

O tutorial inicial usa apenas o mínimo. Depois dele, siga para Construindo workflows e consulte a referência completa de palavras-chave.

3

Valide antes de executar

swf validate workflow.yaml
swf plan workflow.yaml

validate procura erros de configuração. plan mostra o que será executado e em qual ordem.

4

Execute

swf run workflow.yaml

Em um terminal interativo com o extra TUI instalado, a interface em tela cheia é escolhida automaticamente. Para exigir a TUI:

swf run workflow.yaml --ui tui

3. Entendendo a tela

A aba Monitor é o ponto de partida. Ela mostra o workflow à esquerda e os detalhes do item selecionado à direita.

Workflow

Árvore de tarefas e dependências. A seleção acompanha o teclado.

Inspector

Status, tentativa, duração, comando, recursos e arquivos disponíveis da tarefa selecionada.

O painel que contém o foco recebe destaque visual. Assim você sabe onde ↑, ↓ e Enter vão atuar.

4. Navegação pelo teclado

Você não precisa usar o mouse. O conteúdo principal recebe foco automaticamente ao abrir uma aba.

TeclaAção
↑ / ↓Navega no conteúdo do painel ativo.
pNo Monitor, alterna entre os painéis Workflow e Inspector.
EnterAbre ou seleciona o item atual quando a tela oferece uma ação.
/Abre filtro/busca quando disponível.
lAbre Logs da tarefa selecionada.
rAtualiza o estado agora.
sSalva screenshot SVG da tela atual.
? / F1Abre a ajuda completa.
qFecha o monitor. Não cancela o workflow.

Atalhos numéricos para abas

Os números ficam na ajuda para não poluir o rodapé. Em workflows simples: 1 Monitor, 2 Problemas, 3 Logs. Em workflows com ciclos: 1 Monitor, 2 Ciclos, 3 Campanha, 4 Problemas, 5 Logs.

5. O que cada aba responde?

Monitor

“O que está acontecendo agora?”
Árvore do workflow + detalhes da tarefa.

Problemas

“O que exige minha atenção?”
Falhas, entradas/saídas inválidas, bloqueios e outros estados problemáticos.

Logs

“O que o processo escreveu?”
stdout/stderr da tentativa selecionada e acompanhamento de arquivo em execução.

Ciclos

“Como os processos estão distribuídos entre os ciclos?”
Aparece somente quando o workflow possui ciclos.

Campanha

“Como está o conjunto de ciclos ao longo dos dias?”
Resumo operacional da campanha.

Regra de interface: workflows sem ciclos não mostram Ciclos nem Campanha. A TUI apresenta apenas conceitos que realmente existem naquele workflow.

6. Entendendo os estados

EstadoSignificado práticoO que fazer
pendingA tarefa ainda aguarda execução.Normal enquanto dependências não terminaram.
runningHá uma tentativa em andamento.Veja Inspector ou Logs se precisar acompanhar.
successA tarefa terminou e seus contratos foram aceitos.Nenhuma ação.
skippedA tarefa foi deliberadamente pulada/desabilitada.Verifique se era esperado.
failedO processo falhou ou terminou com erro.Abra Problemas e stderr.
invalid-inputUma entrada obrigatória não satisfaz o contrato.Corrija/forneça a entrada.
invalid-outputO processo terminou, mas a saída esperada não passou na validação.Examine stdout/stderr e a regra de saída.
blockedUma dependência impede a execução desta tarefa.Resolva primeiro a tarefa antecedente.

7. Quando algo falhar

Use sempre a mesma sequência. Ela evita procurar arquivos manualmente sem necessidade.

1

Abra Problemas

A aba concentra somente o que precisa de atenção. Use / para filtrar por tarefa, estado, ciclo ou motivo.

2

Selecione o problema

O simpleWorkflow preserva tarefa/ciclo e procura a evidência mais útil disponível.

3

Leia stderr/stdout

No Inspector, selecionar stdout ou stderr leva diretamente à aba Logs. Para uma tarefa em execução, o viewer pode acompanhar o arquivo enquanto ele cresce.

Importante: fechar a TUI com q fecha o monitor, mas não é um comando de cancelamento do workflow.

8. Workflows com ciclos

Quando o workflow possui ciclos, a interface acrescenta recursos específicos sem mudar o modelo básico.

Ciclos compara processos entre tempos de ciclo. Campanha resume vários ciclos por dia. O bloco de período/ciclagem no Inspector só aparece quando possui informação suficiente para justificar o espaço.

9. Onde ficam estado e logs?

Por padrão, o diretório é criado ao lado do YAML:

meu-workflow/
├── workflow.yaml
└── .simpleworkflow/
    ├── state.sqlite3
    ├── lock
    └── runs/
        └── .../attempt-001/
            ├── stdout.log
            ├── stderr.log
            └── metadata.json

Uma pasta .simpleworkflow representa um único workflow lógico. Não use a mesma pasta de estado para YAMLs independentes.

Para observar um workflow já executado ou em execução a partir de outro terminal:

swf monitor workflow.yaml

10. Comandos que você vai usar

ComandoQuando usar
swf validate workflow.yamlAntes de executar; verifica a configuração.
swf plan workflow.yamlPara entender ordem e dependências.
swf run workflow.yamlExecuta o workflow.
swf run workflow.yaml --ui tuiExige a interface interativa.
swf run workflow.yaml --ui plainForça saída simples, útil em logs, batch e CI.
swf status workflow.yamlMostra o estado persistido sem executar.
swf explain workflow.yamlAjuda a entender decisões/estado do workflow.
swf monitor workflow.yamlAbre a TUI somente para observar o estado existente.
swf run workflow.yaml --forceExecuta novamente tarefas que poderiam ser reutilizadas.
swf reset workflow.yamlLimpa o estado reutilizável atual preservando histórico.

11. Problemas comuns

“A TUI não abre.”

Confirme que instalou simpleworkflow[tui]. Em batch, pipes, CI ou terminais não interativos, auto usa propositalmente a saída plain.

“Quero ver a TUI mesmo assim.”

swf run workflow.yaml --ui tui

“Não consigo navegar.”

Ao abrir uma aba, o conteúdo principal deve receber foco automaticamente. Use ↑/↓. No Monitor, p alterna Workflow e Inspector. ? mostra todos os atalhos disponíveis.

“Executei de novo e a tarefa não rodou.”

Uma tarefa concluída pode ser reutilizada quando sua assinatura e seus contratos ainda são válidos. Use --force quando a intenção for realmente criar uma nova execução.

“Tenho dois arquivos YAML na mesma pasta.”

Por padrão eles tentariam usar a mesma .simpleworkflow/. Como uma pasta de estado pertence a um único workflow lógico, coloque workflows independentes em diretórios próprios ou use --workdir deliberadamente.
