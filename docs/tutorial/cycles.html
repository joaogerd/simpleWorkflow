1. Modelo mental

Workflow
├── Initialization   ← uma vez
└── Cycles
    ├── 00Z
    │   ├── ingest
    │   └── process
    ├── 06Z
    │   ├── ingest
    │   └── process
    └── 12Z
        ├── ingest
        └── process

O YAML define o processo uma vez. O simpleWorkflow cria instâncias de tarefa por ciclo no mesmo estado persistente.

2. Inicialização executada uma vez

initialization:
  tasks:
    - name: initialize_workspace
      argv: [python, initialize.py]
      outputs:
        required:
          - work/initialized.txt

initialization.tasks usa o mesmo schema de tarefas normais, mas fica fora do intervalo de ciclos. Em restart, tarefas de inicialização bem-sucedidas podem ser reutilizadas.

Initialization ocorre antes do primeiro ciclo. Se ela falhar, nenhum ciclo começa.

3. Declarando a campanha

Forma com início/fim:

cycle:
  start: "2026-10-03T00:00:00Z"
  end: "2026-10-03T18:00:00Z"
  step: PT6H

Isso gera quatro ciclos inclusivos: 00Z, 06Z, 12Z e 18Z.

Forma equivalente por duração:

cycle:
  start: "2026-10-03T00:00:00Z"
  duration: PT18H
  interval: PT6H

Use exatamente um de end/duration e um de step/interval.

5. Executando tarefas só em certas posições

cycle_scopeExecuta em
allTodos os ciclos (default).
firstSomente primeiro ciclo.
not_firstTodos menos o primeiro.
lastSomente último ciclo.
not_lastTodos menos o último.
- name: campaign_start
  cycle_scope: first
  argv: [python, start.py, "{cycle_time}"]

- name: compare_previous
  cycle_scope: not_first
  argv: [python, compare.py, "{previous_cycle_time}", "{cycle_time}"]

- name: final_summary
  cycle_scope: last
  argv: [python, summary.py, "{cycle_time}"]

6. Dependências dentro de cada ciclo

tasks:
  - name: ingest
    argv: [python, ingest.py, "{cycle_time}"]

  - name: process
    depends_on: [ingest]
    argv: [python, process.py, "{cycle_time}"]

A campanha é executada sequencialmente por ciclo e de forma fail-fast. O ciclo seguinte só é liberado depois que o ciclo atual termina com sucesso.

Isso permite produzir dados no ciclo atual que serão utilizados pelo seguinte sem criar um daemon esperando arquivos.

7. Executando apenas parte da campanha

Um ciclo específico:

swf run workflow.yaml --cycle-time 2026-10-03T06:00:00Z

Vários ciclos específicos:

swf run workflow.yaml \
  --cycle-time 2026-10-03T06:00:00Z \
  --cycle-time 2026-10-03T12:00:00Z

Ou sobrescreva temporariamente o intervalo:

swf run workflow.yaml \
  --from 2026-10-03T06:00:00Z \
  --to   2026-10-03T18:00:00Z \
  --step PT6H
--cycle-time não pode ser combinado com --from, --to ou --step.

9. Exemplo completo de campanha

format_version: 1

workflow:
  name: campanha_exemplo

context:
  python: python
  work: campaign-work

initialization:
  tasks:
    - name: initialize
      argv:
        - "{python}"
        - -c
        - "from pathlib import Path; Path('{work}').mkdir(exist_ok=True)"
      outputs:
        required: ["{work}"]

cycle:
  start: "2026-10-03T00:00:00Z"
  end: "2026-10-03T18:00:00Z"
  step: PT6H

tasks:
  - name: ingest
    argv: ["{python}", ingest.py, "{cycle_yyyymmddhh}"]

  - name: process
    depends_on: [ingest]
    argv: ["{python}", process.py, "{cycle_yyyymmddhh}"]

  - name: compare_previous
    cycle_scope: not_first
    depends_on: [process]
    argv: ["{python}", compare.py, "{previous_cycle_yyyymmddhh}", "{cycle_yyyymmddhh}"]

  - name: final_summary
    cycle_scope: last
    depends_on: [process]
    argv: ["{python}", summary.py]
