# simpleWorkflow 0.5.0 Professional TUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate the already-refined professional Textual TUI from `ux/professional-terminal` with the 0.4.0 SQLite state model, preserving the plain `TerminalReporter` path and making interactive monitoring restart-safe.

**Architecture:** `WorkflowState/state.sqlite3` remains the single source of truth. A presentation-independent read model (`MonitorSnapshot`) reads persisted workflow/cycle/task/run/attempt/history data plus optional attempt files. Textual consumes snapshots only; the engine never imports Textual or widgets. `swf monitor` is read-only attach, while `swf run --ui auto|tui|plain` chooses between Textual and the existing `TerminalReporter` without changing workflow semantics.

**Tech Stack:** Python >=3.10, SQLite, Textual 8.x, Rich 13.x, pytest, Ruff, mypy.

**Spec:** User-approved integration specification in the 2026-09-15 project conversation; historical executable UX reference is PR #14 / branch `ux/professional-terminal`.

## Global Constraints

- Target version is 0.5.0; 0.4.1 remains available for 0.4.x bugfixes.
- Do not change SQLite schema solely for the TUI.
- Do not change engine execution semantics to support the TUI.
- Do not add daemon, server, socket service, REST API, or multi-workflow orchestration.
- `TerminalReporter` remains the non-interactive frontend.
- `swf monitor` opens state read-only and must survive missing optional attempt/log files.
- Textual/Rich remain optional through the `[tui]` extra.
- `--ui auto` is the default for `run`; non-TTY, pipes, files, PBS/CI-style stdout, `TERM=dumb`, or missing optional TUI dependencies fall back to plain output.
- `--ui tui` is explicit and fails clearly if the optional TUI dependencies are unavailable.
- `q` exits the monitor; it never silently cancels workflow execution.
- UI refresh is approximately 1 Hz unless an event-driven refresh is already available.
- Preserve the approved views: Monitor, Ciclos, Campanha, Problemas, Logs; no permanent Help tab and no `Matriz` label.
